4 格式化

术语说明：类代码块结构是指类、方法、构造函数或 switch 的主体。请注意，根据第 4.8.3.1 节关于数组初始化器的规定，任何数组初始化器都可以选择性地被视为类代码块结构。

4.1 大括号

4.1.1 可选大括号的使用

大括号用于 if、 else、 for、 do 和 while 语句，即使其主体为空或仅包含单条语句。

其他可选大括号（例如 lambda 表达式中的大括号）仍然是可选的。

4.1.2 非空代码块：K & R 风格

对于非空代码块和类代码块结构，大括号遵循 Kernighan 和 Ritchie 风格：

  • 左大括号前不换行，下文详述的情况除外。
  • 左大括号后换行。
  • 右大括号前换行。
  • 仅当右大括号结束一条语句，或结束方法、构造函数或具名类的主体时，右大括号后才换行。 例如，如果右大括号后面跟着 else 或逗号，则右大括号后不换行。

例外：在这些规则允许出现以分号（;）结尾的单条语句的地方，可以出现语句代码块，且该代码块的左大括号前要换行。引入此类代码块通常是为了限制局部变量的作用域。

示例：

return () -> {
  while (condition()) {
    method();
  }
};

return new MyClass() {
  @Override public void method() {
    if (condition()) {
      try {
        something();
      } catch (ProblemException e) {
        recover();
      }
    } else if (otherCondition()) {
      somethingElse();
    } else {
      lastThing();
    }
    {
      int x = foo();
      frob(x);
    }
  }
};

第 4.8.1 节枚举类中给出了枚举类的一些例外情况。

4.1.3 空代码块：可以采用简洁写法

空代码块或类代码块结构可以采用 K & R 风格（如第 4.1.2 节所述）。或者，也可以在左大括号后立即闭合，中间不包含任何字符或换行（{}），除非它是多代码块语句（直接包含多个代码块的语句：if/else 或 try/catch/finally）的一部分。

示例：

  // This is acceptable
  void doNothing() {}

  // This is equally acceptable
  void doNothingElse() {
  }

  // This is not acceptable: No concise empty blocks in a multi-block statement
  try {
    doSomething();
  } catch (Exception e) {}

4.2 代码块缩进：+2 个空格

每当开始一个新的代码块或类代码块结构时，缩进增加两个空格。当代码块结束时，缩进恢复到之前的缩进级别。缩进级别适用于整个代码块中的代码和注释。（参见第 4.1.2 节非空代码块：K & R 风格中的示例。）

4.3 每行一条语句

每条语句后都需换行。

4.4 列数限制：100

Java 代码的列数限制为 100 个字符。“字符”是指任何 Unicode 码位。除下文指出的情况外，任何超出此限制的行都必须按第 4.5 节折行中的说明进行折行。

每个 Unicode 码位都计为一个字符，即使其显示宽度更大或更小。例如，如果使用全角字符，你可以选择比本规则严格要求的位置更早地折行。

例外情况：

  1. 不可能遵守列数限制的行（例如，Javadoc 中的长 URL，或长 JSNI 方法引用）。
  2. package 声明和导入语句（参见第 3.2 节包声明和第 3.3 节导入）。
  3. 文本块的内容。
  4. 注释中可能需要复制并粘贴到 shell 中的命令行。
  5. 极少数情况下需要使用非常长的标识符，这类标识符允许超出列数限制。在这种情况下，周围代码的有效折行方式应与 google-java-format 生成的结果一致。

4.5 折行

术语说明：当原本可能占据单行的代码被拆分为多行时，这种操作称为折行。

并没有全面、确定性的公式可以准确指出在每种情况下应该如何折行。很多时候，同一段代码有多种有效的折行方式。

注意：虽然折行的典型原因是避免超出列数限制，但即使代码实际上并未超出列数限制，作者也可以自行决定将其折行。

提示：提取方法或局部变量或许可以在无需折行的情况下解决问题。

4.5.1 在何处断开

折行的首要准则是：优先在更高的语法层级处断开。此外：

  1. 如果在非赋值运算符处断开一行，那么断开位置在该符号之前。（请注意，这与 Google 风格在其他语言（如 C++ 和 JavaScript）中的做法不同。）
    • 这也适用于以下“类运算符”符号：
      • 点分隔符（.）
      • 方法引用的两个冒号（::）
      • 类型边界中的与符号（<T extends Foo & Bar>）
      • catch 代码块中的竖线（catch (FooException | BarException e)）。
  2. 如果在赋值运算符处断开一行，断开位置通常在该符号之后，但两种方式都是可以接受的。
    • 这也适用于增强型 for（“foreach”）语句中的冒号。
  3. 方法名、构造函数名或记录类名与其后面的左圆括号（(）保持在同一行。
  4. 逗号（,）与其前面的记号保持在同一行。
  5. 绝不在紧邻 lambda 或 switch 规则中的箭头处断开一行，除非箭头后面的文本由单个不带大括号的表达式组成，此时可以在箭头后立即断开。示例： 
    MyLambda<String, Long, Object> lambda =
    (String label, Long value, Object obj) -> {
      ...
    };

Predicate<String> predicate = str ->
    longExpressionInvolving(str);

switch (x) {
  case ColorPoint(Color color, Point(int x, int y)) ->
      handleColorPoint(color, x, y);
  ...
}

注意：折行的主要目标是让代码清晰，而不一定是让代码占据最少的行数。

4.5.2 续行缩进至少 +4 个空格

折行时，第一行之后的每一行（即每个续行）相对于原始行至少缩进 +4 个空格。

当存在多个续行时，缩进可以根据需要超过 +4 个空格。通常，当且仅当两个续行以语法上平行的元素开头时，它们才使用相同的缩进级别。

第 4.6.3 节关于水平对齐的内容阐述了不鼓励使用可变数量的空格来将某些记号与前面的行对齐的做法。
